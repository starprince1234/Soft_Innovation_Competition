# **“稽古云语”项目软件系统开发总纲（终终终终稿）**

## **1. 项目概述**

### **1.1 项目核心目标**

本项目旨在4周内，开发并部署一套融合RAG-LLM与自研对象检测模型的文物智能问答与识别平台——“稽古云语”。核心功能包括文物拍摄识别、低幻觉多轮对话（含百度千帆 AI 搜索补充）、**文物列表浏览**、历史记录管理（**含清空历史**）、用户反馈提交（**含截图**）与管理机制、**安全登出、服务健康检查**。系统将支持公众、考古人员、博物馆管理者三类用户层级的功能差异与权限控制，**并确保所有API遵循统一规范，内部API具备鉴权机制**，完成前后端及百度云端容器化部署的MVP版本。

### **1.2 核心技术栈**

* **后端:** Java (Spring Boot) + Python (FastAPI)
* **AI/ML:** 百度飞桨 PaddleDetection (PP-YOLOE+模型), ERNIE-4.5-VL (百度千帆大模型平台), RAG (ChromaDB + Sentence-BERT嵌入), **百度千帆 AI 搜索 API**
* **数据库:** MySQL (持久化存储), Redis (缓存, 会话, 短时上下文, **JWT黑名单**)
* **前端:** 微信小程序 (UniApp), 安卓原生开发 (Kotlin/Java + Jetpack Compose)
* **云架构:** 百度智能云 (BCC/BOS/CDN)
* **容器化:** Docker, Docker Compose
* **其他:** Nginx (反向代理, 静态资源服务)

### **1.3 团队与角色分工**

* **项目负责人/技术导师（你）：** 统筹协调，API接口最终把关，技术选型和疑难解答，推动部署上线，指导权限与安全，协调前后端与AI团队。
* **后端开发（2人）：**
 * **后端A (Java核心逻辑):** 用户认证、权限管理、BOS集成、MySQL/Redis数据操作、Python服务调用（**含内部鉴权**）、API接口实现、用户反馈数据存储与管理、**登出、文物列表、健康检查、清空对话历史、统一API规范**。
 * **后端B (Python AI逻辑):** PP-YOLOE+模型接口对接、RAG实现（Chroma+ERNIE-4.5-VL）、集成千帆 AI 搜索 API，多轮对话管理、角色感知型知识检索与回复、**内部API鉴权**。
* **安卓原生开发（1人）：** 安卓客户端UI、功能实现、API调用、角色适配UI，用户反馈提交与管理界面，**文物列表浏览、登出功能**。
* **UniApp开发（1人）：** 微信小程序UI、功能实现、API调用、角色适配UI，用户反馈提交与管理界面，**文物列表浏览、登出功能**。

### **1.4 总体指导思想**

1. **API先行，持续沟通：** API文档是前后端协作的唯一“合同”，必须在初期全面定义，并保持迭代更新。尤其要明确每个API的权限要求及**统一规范**。
2. **小步快跑，快速迭代：** 4周时间紧张，每周都应有可交付的核心功能。
3. **国产化优先：** 充分利用百度飞桨、百度智能云、百度千帆等国产化技术栈。
4. **化繁为简：** 对于新手，优先使用成熟框架和库，避免过度造轮子。
5. **高频协作：** 每天站会，即时解决阻塞，保持透明度。

## **3. 数据库Schema设计（终稿）**

**MySQL Tables:**

1. **`users` 表**
 * `id` (BIGINT, Primary Key, Auto Increment)
 * `username` (VARCHAR(255), Unique, Not Null) - 用户名
 * `password_hash` (VARCHAR(255), Not Null) - 密码哈希
 * `role` (VARCHAR(50), Not Null, Default 'PUBLIC') - 用户角色: 'PUBLIC', 'ARCHAEOLOGIST', 'MANAGER'
 * `created_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP)
 * `updated_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP)
 * `status` (VARCHAR(20), Not Null, Default 'ACTIVE') - 用户状态: 'ACTIVE', 'INACTIVE'
 * `last_login_at` (DATETIME)

2. **`detection_tasks` 表**
 * `id` (BIGINT, Primary Key, Auto Increment)
 * `user_id` (BIGINT, Not Null, Foreign Key -> `users.id`)
 * `image_url` (VARCHAR(512), Not Null) - BOS 图片 URL
 * `status` (VARCHAR(20), Not Null, Default 'PENDING') - 任务状态: 'PENDING', 'PROCESSING', 'COMPLETED', 'FAILED'
 * `detected_label` (VARCHAR(255)) - 识别出的文物名称
 * `confidence` (FLOAT) - 置信度
 * `bbox` (TEXT) - 边界框信息 (JSON字符串: `[x1, y1, x2, y2]`)
 * `raw_result` (TEXT) - 模型返回的原始结果 (JSON字符串，可选)
 * `created_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP)
 * `updated_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP)
 * `team_id` (BIGINT, Optional, Foreign Key -> `teams.id`) - 关联团队ID (如果实现团队功能)

3. **`dialog_records` 表**
 * `id` (BIGINT, Primary Key, Auto Increment)
 * `user_id` (BIGINT, Not Null, Foreign Key -> `users.id`)
 * `artifact_id` (BIGINT, Optional, Foreign Key -> `artifacts.id`) - 关联的文物ID (如果对话基于识别)
 * `turn_id` (INT, Not Null) - 对话轮次
 * `user_query` (TEXT, Not Null) - 用户提问
 * `ai_response` (TEXT, Not Null) - AI回复
 * `context_snapshot` (TEXT) - 本轮对话前的上下文快照 (JSON字符串，可选)
 * `rag_sources` (TEXT) - RAG检索到的知识来源 (JSON字符串，包含本地RAG和千帆搜索来源，可选)
 * `created_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP)
 * `team_id` (BIGINT, Optional, Foreign Key -> `teams.id`) - 关联团队ID (如果实现团队功能)

4. **`artifacts` 表 (文物知识库)**
 * `id` (BIGINT, Primary Key, Auto Increment)
 * `name` (VARCHAR(255), Unique, Not Null) - 文物名称
 * `description` (LONGTEXT) - 文物详细描述
 * `image_url` (VARCHAR(512)) - BOS 存储的文物图片 URL
 * `thumbnail_url` (VARCHAR(512)) - 缩略图 URL
 * `tags` (VARCHAR(512)) - 标签 (逗号分隔，如 "唐朝,青花瓷")
 * `location` (VARCHAR(255)) - 发现地点/收藏地点
 * `era` (VARCHAR(255)) - 文物年代
 * `creator_id` (BIGINT, Optional, Foreign Key -> `users.id`) - 提交者ID (考古人员)
 * `status` (VARCHAR(20), Not Null, Default 'APPROVED') - 审核状态: 'PENDING', 'APPROVED', 'REJECTED'
 * `vector_embedding_id` (VARCHAR(255)) - 关联ChromaDB的向量ID (便于管理)
 * `created_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP)
 * `updated_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP)

5. **`feedback` 表**
 * `id` (BIGINT, Primary Key, Auto Increment)
 * `user_id` (BIGINT, Optional, Foreign Key -> `users.id`) - 提交用户ID (匿名用户可为NULL)
 * `type` (VARCHAR(50), Not Null, Default 'GENERAL') - 反馈类型: 'BUG', 'FEATURE_REQUEST', 'CONTENT_ERROR', 'GENERAL'
 * `text_content` (TEXT, Not Null) - 反馈内容
 * `rating` (INT) - 评分 (1-5，可选)
 * `screenshot_url` (VARCHAR(512)) - 截图URL (新增，BOS存储)
 * `status` (VARCHAR(20), Not Null, Default 'PENDING') - 处理状态: 'PENDING', 'REVIEWED', 'RESOLVED'
 * `handler_id` (BIGINT, Optional, Foreign Key -> `users.id`) - 处理人ID
 * `created_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP)
 * `updated_at` (DATETIME, Not Null, Default CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP)

**`teams` 表**
* `id` (BIGINT, Primary Key, Auto Increment)
* `name` (VARCHAR(255), Not Null)
* `owner_id` (BIGINT, Foreign Key -> `users.id`)
* `created_at` (DATETIME)

** `user_team_membership` 表**
* `user_id` (BIGINT, Foreign Key -> `users.id`)
* `team_id` (BIGINT, Foreign Key -> `teams.id`)
* `role_in_team` (VARCHAR(50)) - 如 'MEMBER', 'ADMIN'
* `joined_at` (DATETIME)

**Redis Keys (示例):**

* `jwt_blacklist:{token_hash}`: JWT黑名单 (用于登出或过期)
* `user:{user_id}:session_token`: 用户会话Token (可选，如果Session管理更复杂)
* `dialog_context:{user_id}`: 最近N轮对话上下文 (JSON字符串)
* `detect_task_status:{task_id}`: 检测任务状态和临时结果 (JSON字符串)
* `qianfan_search_cache:{query_hash}`: 千帆 AI 搜索结果缓存 (JSON字符串，含补充片段和来源)
* `api_rate_limit:{user_id}:{api_path}`: API限流计数

### **4.0 统一API规范**

**所有API的请求和响应必须遵循以下统一规范：**

* **统一响应体格式：**
 * **成功响应 (HTTP Status 200 OK):**
 ```json
 {
 "code": 200, // 业务状态码，200表示成功
 "message": "Success", // 简要消息
 "data": { // 具体的业务数据
 // ... 根据不同接口返回
 }
 }
 ```
 * **错误响应 (HTTP Status Code 对应业务码):**
 ```json
 {
 "code": 400, // HTTP状态码或自定义业务错误码
 "message": "Bad Request", // 简要错误消息
 "details": { // 详细错误信息 (可选)
 "field": "Error description" // 如参数校验失败
 }
 }
 ```
* **统一错误码枚举 (示例):**
 * `200`: Success
 * `400`: Bad Request (请求参数错误、格式不符)
 * `401`: Unauthorized (未认证，JWT缺失或无效)
 * `403`: Forbidden (无权限访问)
 * `404`: Not Found (资源不存在)
 * `409`: Conflict (资源冲突，如用户名已存在)
 * `429`: Too Many Requests (请求频率过高)
 * `500`: Internal Server Error (服务器内部错误)
* **统一分页参数：**
 * 所有需要分页的`GET`请求（列表查询）应使用以下Query Parameters：
 * `page`: 页码 (int, 默认0，从0开始)
 * `size`: 每页大小 (int, 默认10)
 * `sortBy`: 排序字段 (string, 默认`createdAt`或其他相关字段)
 * `direction`: 排序方向 (string, 'asc'或'desc', 默认'desc')
 * 分页响应体应包含：`totalElements`, `totalPages`, `currentPage`, `pageSize`等元数据。

### **4.1 认证与用户管理模块 (后端: Java)**

1. **用户注册**
 * **Method:** `POST /auth/register`
 * **Description:** 用户注册新账户。
 * **Required Role(s):** `permitAll()`
 * **Request Body:** `{"username": "newuser", "password": "strongpassword"}`
 * **Response Body (Success 200):** `{"code": 200, "message": "注册成功", "data": null}`

2. **用户登录**
 * **Method:** `POST /auth/login`
 * **Description:** 用户登录并获取JWT Token。
 * **Required Role(s):** `permitAll()`
 * **Request Body:** `{"username": "existinguser", "password": "strongpassword"}`
 * **Response Body (Success 200):**
 ```json
 {
 "code": 200,
 "message": "登录成功",
 "data": {
 "token": "eyJhbGciOiJIUzI1Ni...",
 "expiresIn": 3600, // Token有效期，秒
 "roles": ["PUBLIC", "ARCHAEOLOGIST"] // 当前用户的所有角色
 }
 }
 ```

3. **用户登出 (高优先级新增)**
 * **Method:** `POST /auth/logout`
 * **Description:** 用户安全登出，使当前JWT失效（加入Redis黑名单）。
 * **Required Role(s):** `@PreAuthorize("isAuthenticated()")`
 * **Request Body:** (无需)
 * **Response Body (Success 200):** `{"code": 200, "message": "登出成功", "data": null}`

4. **获取当前用户信息**
 * **Method:** `GET /users/me`
 * **Description:** 获取当前登录用户的个人信息。
 * **Required Role(s):** `@PreAuthorize("isAuthenticated()")`
 * **Response Body (Success 200):** `{"code": 200, "message": "查询成功", "data": {"id": 1, "username": "currentuser", "role": "ARCHAEOLOGIST", "createdAt": "2023-10-26T10:00:00"}}`

5. **修改当前用户密码**
 * **Method:** `PUT /users/me/password`
 * **Description:** 修改当前登录用户的密码。

 * **Request Body:** `{"oldPassword": "oldstrongpassword", "newPassword": "newstrongpassword"}`
 * **Response Body (Success 200):** `{"code": 200, "message": "密码修改成功", "data": null}`

### **4.2 文物检测与数据录入模块 (后端: Java + Python)**

1. **上传图片并创建检测任务**
 * **Method:** `POST /detect/tasks`
 * **Description:** 前端上传文物图片（Base64编码），Java后端接收并上传至BOS，创建检测任务，异步触发Python后端进行检测。
 * **Required Role(s):** `@PreAuthorize("isAuthenticated()")`
 * **Request Body:** `{"imageBase64": "data:image/jpeg;base64,/9j/4AAQSkZJ..."}`
 * **Response Body (Success 200):** `{"code": 200, "message": "图片上传成功，检测任务已启动", "data": {"taskId": "UUID_OF_TASK", "status": "PENDING"}}`
 * **Java to Python Internal Call:** `POST /internal/detect/process` (Java内部调用Python)
 * **Request Header:** `X-Internal-Token: {INTERNAL_SECRET_TOKEN}`
 * **Request Body:** `{"taskId": "UUID_OF_TASK", "imageUrl": "https://bos.baidu.com/..."}`
 * **Python Logic:**
 1. **内部鉴权：校验`X-Internal-Token`和来源IP。**
 2. 下载图片。调用PP-YOLOE+模型服务获取结果。
 3. 更新MySQL/Redis中`detection_tasks`表的`status`、`detected_label`、`confidence`、`bbox`。

2. **获取检测任务状态**
 * **Method:** `GET /detect/tasks/{taskId}/status`
 * **Description:** 前端轮询检测任务的当前状态。
 * **Required Role(s):** `@PreAuthorize("isAuthenticated()")`
 * **Path Parameter:** `taskId`
 * **Response Body (Success 200):** `{"code": 200, "message": "查询成功", "data": {"taskId": "UUID_OF_TASK", "status": "COMPLETED"}}`

3. **获取检测结果**
 * **Method:** `GET /detect/results/{taskId}`
 * **Description:** 获取指定检测任务的详细结果。
 * **Required Role(s):** `@PreAuthorize("isAuthenticated()")`
 * **Path Parameter:** `taskId`
 * **Response Body (Success 200):**
 ```json
 {
 "code": 200,
 "message": "查询成功",
 "data": {
 "taskId": "UUID_OF_TASK",
 "status": "COMPLETED",
 "detectedArtifacts": [
 {"label": "青铜鼎", "confidence": 0.98, "bbox": [100, 50, 400, 450], "artifactId": 123}
 ],
 "imageUrl": "https://bos.baidu.com/..."
 }
 }
 ```

4. **考古人员提交新文物信息**
 * **Method:** `POST /archaeology/artifacts`
 * **Description:** 考古人员上传新发现文物图片及初步元数据，提交至系统待审核。
 * **Required Role(s):** `@PreAuthorize("hasRole('ARCHAEOLOGIST')")`
 * **Request Body:** `{"name": "未知陶罐", "description": "...", "imageBase64": "...", "location": "...", "era": "...", "tags": ["..."], "notes": "..."}`
 * **Response Body (Success 200):** `{"code": 200, "message": "文物提交成功，待审核", "data": {"artifactId": 456, "status": "PENDING"}}`

5. **管理者查看待审核文物列表**
 * **Method:** `GET /admin/artifacts/pending`
 * **Description:** 博物馆管理者查看所有考古人员提交的待审核文物列表。
 * **Required Role(s):** `@PreAuthorize("hasRole('MANAGER')")`
 * **Query Parameters:** `page`, `size`, `sortBy`, `direction`
 * **Response Body (Success 200, 遵循分页规范):**
 ```json
 {
 "code": 200,
 "message": "查询成功",
 "data": {
 "totalElements": 5, "totalPages": 1, "currentPage": 0, "pageSize": 10,
 "list": [
 {"id": 456, "name": "未知陶罐", "creator": "考古人员B", "status": "PENDING", "submittedAt": "2023-10-25T14:30:00", "thumbnailUrl": "https://bos.baidu.com/thumb_unknown_pot.jpg"}
 ]
 }
 }
 ```

6. **管理者审核文物**

2. **幻觉抑制与跨模态语义对齐：**
 * **方案：** 在LLM的Prompt中明确指示“仅基于提供的信息回答，若无法回答则明确说明”。结合千帆搜索结果的去重、优先级排序和来源溯源来增强幻觉抑制。初期可简化为将视觉识别出的文物名称直接作为RAG检索和LLM对话的“锚点”。

3. **前后端API对接与数据格式：**
 * **方案：** **严格遵守API文档**。任何接口改动必须同步更新文档并通知所有相关成员。使用Postman/Swagger进行接口测试，确保数据格式（JSON字段名、类型）一致。特别注意Python后端接收`localRagConfidenceThreshold`参数的正确性。**强调所有接口必须严格遵循统一响应体、错误码、分页参数规范。**
 * **你的指导：** 在第一周投入足够时间进行API设计，并在后续开发中持续审查API调用。

4. **Docker容器化部署：**
 * **方案：** 从`docker-compose.yml`入手，先让萌新理解每个服务的配置。提供Java和Python服务的`Dockerfile`模板，解释每条指令的作用。强调容器化是为了简化部署。

5. **Redis+MySQL双存储设计：**
 * **方案：** 明确Redis主要用于缓存、会话、短时上下文数据（如最近N轮对话、千帆搜索结果、**JWT黑名单**），MySQL用于持久化存储核心业务数据。强调双写时优先保证MySQL写入成功，Redis作为辅助缓存。
 * **你的指导：** 解释两种数据库的适用场景，帮助他们设计数据同步逻辑，**特别是千帆搜索结果和JWT黑名单的缓存策略。**

 * **你的指导：** 详细讲解Spring Security的工作原理，提供示例代码，并反复强调权限控制的重要性。

7. **千帆 AI 搜索集成：**
 * **方案：** 萌新调用外部API可能会有疑问。提供封装好的`requests`库调用示例，强调API Key的安全管理（环境变量），并讲解好触发条件和数据融合逻辑。由于该功能主要在Python后端实现，对前端无感，可以减少前端同学的担忧。
 * **你的指导：** 详细讲解百度千帆平台的使用，带领后端B同学理解千帆 AI 搜索 API的参数和响应结构，帮助他们实现封装和内部调用逻辑，并调试数据融合和去重算法。

8. **JWT安全注销 (新增痛点):**
 * **方案：** JWT无状态的特性导致无法直接注销。最常用的方式是维护一个JWT黑名单（或称Revocation List）。当用户登出时，将当前JWT的哈希或整个Token存入Redis，设置过期时间与JWT的剩余有效期相同。每次请求时，除了验证JWT有效性，还要检查它是否在黑名单中。
 * **你的指导：** 详细讲解JWT原理、为什么需要黑名单、如何在Redis中高效实现黑名单，并指导后端A同学集成。

9. **内部API鉴权 (新增痛点):**
 * **方案：** 确保Java调用Python服务的API是安全的，不被外部直接访问。通过约定一个固定的`X-Internal-Token`请求头和配置内网IP白名单，Python端对这些内部接口进行严格校验。
 * **你的指导：** 强调内网安全的重要性，指导后端B同学在FastAPI中实现中间件或装饰器来校验这些安全凭证。

10. **统一API规范落地 (新增痛点):**
 * **方案：** 对于萌新，统一规范往往容易被忽视或执行不到位。在API设计阶段就强制使用模板，并在代码审查时严格检查。后端Java可以封装一个统一的`ResponseEntity`或`ControllerAdvice`来处理响应格式和错误码。前端则统一封装网络请求，自动解析响应格式。
 * **你的指导：** 在第一周投入充足时间带领团队制定并理解这些规范，并在后续开发中持续跟进，强调“先有规范，后有代码”的原则。
